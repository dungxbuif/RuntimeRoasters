# [RR-11] Traceability GraphQL Engine

- **Summary:** Triển khai GraphQL Endpoint chuyên biệt trong Trace Service để truy vấn đồ thị vòng đời sản phẩm.
- **Priority:** `HIGH`
- **Depends on:** `RR-10` (Trace Service & Elasticsearch data)
- **Description:** Đây là hiện thực hóa **Phương án C (Traceability Graph Engine)** theo thiết kế tại [`docs/architecture/graphql-integration.md`](../../architecture/graphql-integration.md). Endpoint `/trace/graphql` cho phép khách hàng quét mã QR và nhận toàn bộ hành trình sản phẩm trong một query duy nhất, đi sâu từng tầng theo ý muốn của UI.

---

## 🔍 Acceptance Criteria (BDD Specification)

### Scenario 1: Truy vấn vòng đời cơ bản qua QR Code
- **Given:** Elasticsearch đã có document cho `qr_code = "RR-2024-001-ABC"` với đầy đủ lifecycle.
- **When:** Client gửi GraphQL query:
  ```graphql
  query {
    traceByQR(qrCode: "RR-2024-001-ABC") {
      product { name variety }
      harvestLot { farmName region harvestedAt }
      roastBatch { roastLevel roastedAt }
    }
  }
  ```
- **Then:** Server trả về JSON đúng cấu trúc, không có field `null` nếu dữ liệu tồn tại. Latency < 200ms.

### Scenario 2: Truy vấn đồ thị sâu nhiều tầng
- **Given:** Dữ liệu Elasticsearch đã có đầy đủ lifecycle từ Farm đến Retail.
- **When:** Client query toàn bộ chuỗi: `traceByQR ➔ shipment ➔ roastBatch ➔ harvestLot ➔ lifecycleEvents`.
- **Then:** Server trả về dữ liệu đúng, không có N+1 query thêm nào sang các service khác. Mọi dữ liệu đến từ Elasticsearch DSL duy nhất.

### Scenario 3: Query Complexity giới hạn tài nguyên
- **Given:** Một client cố tình gửi query lồng nhau 10 cấp với mục đích làm cạn kiệt tài nguyên.
- **When:** Server tính tổng complexity của query.
- **Then:** Nếu tổng complexity > 50, server từ chối với lỗi `400 Bad Request: query complexity exceeded`. Request không chạm đến Elasticsearch.

### Scenario 4: Casbin Authorization tại Resolver
- **Given:** Request đến với JWT của user có role `customer`.
- **When:** Resolver `traceByQR` được gọi.
- **Then:** Casbin cho phép truy cập (policy: `customer` có quyền đọc `trace:read`). Nếu role không hợp lệ (ví dụ: anonymous không có JWT), trả về `401 Unauthorized`.

## 🛠️ Technical Notes

### Toolchain
- **Schema Generator:** `gqlgen` (Schema-First). File schema tại `apps/trace-service/graph/schema.graphql`.
- **Query-to-ES DSL:** Implement `ElasticsearchQueryBuilder` tại lớp Infrastructure của Trace Service.
- **Complexity Config:**
  ```go
  handler.AddTransport(transport.POST{})
  handler.Use(extension.FixedComplexityLimit(50))
  ```

### Endpoint Registration (thêm vào Trace Service HTTP Router)
```go
// apps/trace-service/internal/delivery/http/router.go
router.POST("/trace/graphql", graphqlHandler)
router.GET("/trace/graphql", playground.Handler("Trace Playground", "/trace/graphql"))
```

### Casbin Policy (thêm vào policy.csv)
```
p, customer, trace:read, read
p, admin,    trace:read, read
p, admin,    trace:write, write
```

### Schema File (Schema-First với gqlgen)
Tham khảo định nghĩa đầy đủ tại `docs/architecture/graphql-integration.md` — Section 6.
