<task type="auto" tdd="true">
  <name>Task 1: Shipment State Machine with Failure Paths</name>
  <files>src/apps/logistics-service/internal/usecase/shipment_lifecycle.go</files>
  <behavior>
    - Valid transitions:
      - PENDING -> ASSIGNED (System assignment)
      - ASSIGNED -> PICKED_UP (Driver confirms pickup)
      - PICKED_UP -> IN_TRANSIT (System/Driver starts journey)
      - IN_TRANSIT -> DELIVERED (Driver confirms delivery)
      - ASSIGNED -> PENDING (Driver rejects assignment - must mark driver as available again)
      - PICKED_UP/IN_TRANSIT -> FAILED (Breakdowns/Accidents - WR-04)
      - PENDING/ASSIGNED -> CANCELLED (Order cancelled - WR-04)
    - Rejection should trigger a re-assignment (set to PENDING and let DispatchWorker pick it up).
    - Every transition involving a driver (Accept/Reject/Complete) must update the `Driver.IsAvailable` status atomically.
  </behavior>
  <action>
    - Implement `UpdateShipmentStatus` use case with state validation.
    - Ensure every state change is atomic and recorded in the database.
    - Implement `RejectAssignment` specifically to handle the `ASSIGNED -> PENDING` transition and driver cleanup.
  </action>
  <verify>
    <automated>go test -v ./src/apps/logistics-service/internal/usecase/shipment_lifecycle_test.go</automated>
  </verify>
