# [RR-10] Trace Service — Kafka Consumer & Elasticsearch Indexing

- **Summary:** Xây dựng Trace Service tiêu thụ event từ Kafka và lưu vào Elasticsearch làm Read Model.
- **Priority:** `HIGH`
- **Depends on:** `RR-9` (Kafka & Outbox)
- **Description:** Trace Service là "người ghi sử" của hệ thống. Nó lắng nghe tất cả các sự kiện lifecycle từ Farm, Process, Logistics và Warehouse, chuẩn hóa thành document Elasticsearch với cấu trúc lồng nhau (nested) để phục vụ Traceability GraphQL Engine ở RR-11.

---

## 🔍 Acceptance Criteria (BDD Specification)

### Scenario 1: Consumer nhận và lưu event Farm
- **Given:** Farm Service publish event `farm.harvest.created` lên Kafka.
- **When:** Trace Service consumer nhận được event.
- **Then:** Một document mới được tạo trong Elasticsearch index `product-lifecycle-{YYYY.MM}` với đầy đủ thông tin: `harvest_lot_id`, `farm_name`, `region`, `variety`, `timestamp`, `qr_code`.

### Scenario 2: Enrich và link các event theo QR Code
- **Given:** Các event từ nhiều service (Farm → Process → Logistics) cùng tham chiếu `batch_id`.
- **When:** Trace Service nhận lần lượt các event này.
- **Then:** Các event được upsert (update or insert) vào cùng một document Elasticsearch, tổng hợp thành cấu trúc vòng đời đầy đủ. Không tạo document trùng lặp.

### Scenario 3: Idempotency — Không xử lý event trùng lặp
- **Given:** Kafka tái gửi một event (do broker restart).
- **When:** Trace Consumer nhận event có `event_id` đã xử lý.
- **Then:** Consumer kiểm tra `event_id` qua Inbox Pattern (DB), bỏ qua event trùng lặp. Elasticsearch document không bị ghi đè sai.

## 🛠️ Technical Notes

- **Elasticsearch Index Mapping:**
  ```json
  {
    "mappings": {
      "properties": {
        "qr_code":        { "type": "keyword" },
        "batch_id":       { "type": "keyword" },
        "current_stage":  { "type": "keyword" },
        "harvest_lot":    { "type": "object" },
        "roast_batch":    { "type": "object" },
        "shipment":       { "type": "nested" },
        "lifecycle_events": {
          "type": "nested",
          "properties": {
            "stage":     { "type": "keyword" },
            "timestamp": { "type": "date" },
            "location":  { "type": "geo_point" },
            "actor":     { "type": "keyword" }
          }
        }
      }
    }
  }
  ```
- **Consumer Group ID:** `trace-service-group` — cùng group_id khi scale lên nhiều replicas.
- **Inbox Pattern:** Dùng bảng `inbox_events` trong Trace Service DB để dedup theo `event_id` (Kafka message key).
