# [RR-10] Client-Side Auth & Login Flow

- **Summary:** Xây dựng luồng đăng nhập và quản lý session tại Client App.
- **Priority:** `HIGH`
- **Type:** Feature

---

## 📖 User Story
> As a user, I want to login with my credentials so that I can access my dashboard and supply chain data securely.

## 🔍 Acceptance Criteria
### Scenario 1: Login Interface
- **Given:** I am at the `/login` route.
- **Then:** I see a login form matching the Design System (Industrial Style).

### Scenario 2: Token Management
- **Given:** I enter valid credentials and submit.
- **When:** The Identity Server returns a JWT.
- **Then:** The token is stored securely (HttpOnly Cookie preferred) and I am redirected to `/`.

### Scenario 3: Authenticated Requests
- **Given:** I am logged in.
- **When:** I perform any action (e.g., Trigger Ping).
- **Then:** The Axios interceptor automatically attaches the `Authorization: Bearer <token>` header.

## 🛠️ Technical Notes
- Implementation: Next.js Middleware for route protection.
- State: Zustand or simple Context to store User profile.
- API: Call KrakenD which proxies to Identity Server.
