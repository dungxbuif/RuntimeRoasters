# FB-20260528-09 Documentation Gap Audit & Streamlining

Status: `IN_PROGRESS`

## Problem Statement

Runtime Roasters has enough documentation to explain the system, but the current structure makes readers work too hard to identify which document is canonical for a given question. Product truth, current technical contracts, demo runbooks, historical implementation notes, UI gap planning, feedback investigations, and story archives are all valuable, but their boundaries are not consistently explicit.

This ticket records a docs-only audit and streamlining plan. It does not perform the large documentation refactor.

## Goals

- Identify documentation gaps, ambiguous ownership, and stale/mixed-current sections.
- Map which documents are canonical, reference-only, planning-only, or archive.
- Propose a phased streamlining plan that can be reviewed before files are moved or rewritten.
- Create a backlog of missing docs that would make the project easier to learn, demo, and maintain.
- Keep the audit grounded in the current repository paths.

## Non-Goals

- No code changes.
- No route, API, seed, or UI behavior changes.
- No deletion or movement of existing documentation.
- No attempt to rewrite `SPEC.md`, `TECH.md`, or `GUIDE.md` in this ticket.
- No promotion of feedback-item truth into product docs until the refactor plan is approved.
